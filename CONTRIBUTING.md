# Contributing to LASP

Thank you for helping test the LASP research prototype. Contributions should make the scope more reproducible, more honest or more secure.

## Before opening a pull request

Run the local syntax and integrity checks described in the README. Explain the tested commit, environment, expected result and any checks that were not executed. Keep real credentials, personal data, network tokens and production integrations out of the repository.

## Evidence language

Use the project vocabulary consistently: `implemented`, `observed`, `simulated`, `planned`, `not_executed`, `external_source` and `not_a_certification`. Do not convert a research reference into a claim that LASP is compliant, certified or production-ready.

## Research and sources

For new security claims, cite the primary specification, study, benchmark or incident report. Distinguish a draft proposal, a browser polyfill, a demo implementation and a final standard. Update the relevant specification or research ledger when behavior changes.

## AI-assisted development

AI tools may assist drafting, coding, testing and research. Contributions must still be reviewed by the person submitting them. Do not add AI systems as legal authors or claim that generated output is independently verified without a test or source.

## Pull requests

Keep changes focused. Include a short rationale, affected scope, tests, security implications and documentation changes. Do not add telemetry, external uploads, real credentials or silent network calls.
